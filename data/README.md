# P13 — Data dictionary + known quirks

## The file as received — `data/raw/orders_SAMPLE.csv`

SAMPLE orders file for the fictional shop **Al-Noor Traders, Lahore**,
Jan–Jun 2026. 1,524 rows = 1,500 orders + 24 exact duplicate copies.
Generated by `src/generate_data.py` (seed 20261109) with 300 defects
planted on purpose — the planted counts live in
`data/raw/defect_manifest.json`, and the audit re-finds every one of
them without reading it.

| Column | Type | Meaning |
|---|---|---|
| order_id | text | `ANT-10001` … `ANT-11500`; the file's key — must be unique |
| order_date | text | ISO `YYYY-MM-DD`; the file claims Jan–Jun 2026 |
| customer_name | text | Customer's name |
| customer_email | text | Must be a valid address; blank = unreachable customer |
| product_code | text | Must exist in the product master (41 products) |
| product_name | text | Product name as written on the order |
| category | text | Must match the product master's category for that code |
| quantity | integer | Must be > 0 |
| unit_price | integer (PKR) | Must be > 0 |
| total_amount | integer (PKR) | Must equal quantity × unit_price |
| payment_method | text | One of: Cash on Delivery, Bank Transfer, JazzCash, Easypaisa, Card |
| city | text | Delivery city |

## The fixed file — `data/processed/orders_FIXED.csv`

Same 12 columns + `audit_flag` (what was fixed or flagged on that row,
or `OK`). 1,500 rows — the 24 duplicate copies are dropped, the rest
are the same orders with the audit's fixes applied. Rows the audit
could not fix honestly keep their original value and a flag that says
so (missing/invalid email, zero price, future date, orphan code).

## The defect register — `outputs/defect_register.csv`

One row per defect (300 rows): `defect_id` (DQ-0001…DQ-0300),
`order_id`, `column`, `defect_type`, `severity` (Critical / High /
Medium), `detail`, `fix_applied`.

## Known quirks (kept, flagged, never silently edited)

- 9 rows have `unit_price = 0` — the price is genuinely missing, so
  the fixed file keeps 0 and flags the row. Do not "fix" these by
  guessing a price.
- 22 rows carry product code `XX-9999` ("UNKNOWN PRODUCT") — the code
  is not in the master, so the audit cannot know what was sold.
- 10 rows are dated after 2026-06-30 (up to 2026-10-04) — the shop
  must confirm whether these are late entries or wrong dates.
- 5 dates were written DD/MM/YYYY (`15/03/2026` style) — re-parsed to
  ISO in the fixed file; the original strings are in the raw file.
- The product master has 41 products across 6 categories; the most
  common payment is Cash on Delivery. Cities are Lahore, Karachi,
  Islamabad, Rawalpindi, Faisalabad, Multan.
- `data/processed/orders.db` is rebuildable from the pushed scripts
  and CSVs (`python3 src/build_sqlite.py`) and is intentionally NOT
  uploaded to GitHub.
